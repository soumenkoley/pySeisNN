# Single-body-wave Newtonian noise for a spherical cavity

This chapter documents `getSphNNSingleBody.ipynb`. The notebook calculates the
Newtonian acceleration generated by one prescribed plane body wave in a
homogeneous medium containing a spherical cavity. It then compares the
numerical volume and boundary integrals against semi-analytic spherical-cavity
expressions.

This is the recommended first example because it isolates one wave type and
one cavity. It tests the numerical geometry and integration before stochastic
source populations or layered Qseis wavefields are introduced.

## What the example demonstrates

The notebook shows how to:

- configure a homogeneous medium and a spherical cavity;
- place a test mass at the cavity centre;
- select a deterministic P, SV, or SH plane wave;
- calculate bulk, vertical-boundary, and horizontal-boundary NN terms;
- combine those terms into the total Newtonian acceleration;
- save frequency-domain results for one realization; and
- validate the numerical calculation with semi-analytic expressions from
  `modules/bodyPSNN.py`.

The example can represent either a full space or a half-space. Body waves are
generated analytically by `modules/simDisp.py`; Qseis Green's functions are not
used to generate the displacement field in this notebook.

## Required files

The notebook expects:

- a main configuration file, such as
  `configParseFullSpaceBodyHomo.ini`;
- a cavity configuration file, such as
  `SingleSphCavityFullSpace.ini`;
- the Python modules under `modules/`; and
- writable Qseis-input and result directories specified in the main
  configuration.

The paths in the notebook are currently absolute and must be changed for a
different installation:

```python
configFile = "/path/to/configParseFullSpaceBodyHomo.ini"
allCavities = configLoader.loadCavities(
    "/path/to/SingleSphCavityFullSpace.ini"
)
```

The complete meaning of the configuration fields is described in
`docs/configuration_complete.md`. The sections below explain the settings that
are especially important for this example.

## Physical model

The tutorial configuration supplied with the notebook uses a homogeneous
model represented by identical finite-layer and half-space properties:

```ini
[model]
thickness = 10000.0, 0.0
vp = 4000.0, 4000.0
vs = 2000.0, 2000.0
rho = 2465.0, 2465.0
qp = 900, 900
qs = 450, 450
rhoAir = 1.2
```

Although two entries are present, the identical elastic parameters make the
medium homogeneous. The final zero thickness denotes the half-space.

The frequency band is

```ini
[frequency]
fmin = 2.0
fmax = 7.9
df = 0.1
```

and the numerical NN grid uses six points per minimum relevant wavelength:

```ini
[grid]
lambda_frac = 0.3333
lambda_res = 6
```

For a convergence study, repeat the calculation with a larger
`lambda_res` and compare the total NN result and numerical error.

## Simulation domain

The supplied full-space configuration uses a domain centred at `(0, 0)` with
horizontal half-widths of 3000 m and a configured depth extent of 6000 m:

```ini
[geometry]
x_center = 0.0
y_center = 0.0
x_extent = 3000
y_extent = 3000
z_extent = 6000
```

The resulting horizontal bounds are `-3000 <= x <= 3000 m` and
`-3000 <= y <= 3000 m`. The numerical geometry initially uses positive depth,
while the NN kernels use an internal Cartesian z coordinate that is negative
underground.

The notebook sets

```python
fullSpace = True
```

to select the full-space boundary treatment. Set it to `False` for a
half-space calculation and use the corresponding half-space main and cavity
configuration files.

For full-space validation, the semi-analytic cell translates the z coordinate
so that the finite box is

```python
outer_bounds = (-L, L, -L, L, -L, L)
```

and the cavity centre is expressed in that translated coordinate system. In a
homogeneous full space, this translation changes the coordinate origin but not
the relative geometry or physical result.

## Spherical cavity and test mass

The cavity file contains one spherical cavity:

```ini
[CavityA]
shape = sphere
xC = 0.0
yC = 0.0
zC = 3000.0
radius = 20.0
xRefineFactor = 6.0
yRefineFactor = 6.0
zRefineFactor = 6.0
```

The centre is 3000 m below the configured surface, and the radius is 20 m.
Depth is entered as a positive number in configuration files.

The example reads all four Einstein Telescope test-mass positions because the
configuration loader requires them. It then selects only `itm_ac`:

```python
itmAll = np.vstack((itmACUse,))
```

The supplied position is `(0, 0, 3000 m)`, so the selected test mass is at the
cavity centre. Before the NN calculation, the notebook converts positive depth
to the internal Cartesian convention:

```python
itmACUse[2] = -np.abs(itmACUse[2])
```

`NNGeometryNN.findTMInCavity` associates the test mass with its host cavity.
This association is used when constructing the locally refined integration
region.

## Adaptive refinement around the cavity

The background grid spacing is calculated per geological layer from the
minimum relevant wavelength:

```python
gridSize = NNCompute.getGridSize(
    thickness, vp, vs, rho, fMin, fMax, lambdaFrac, lambdaRes
)
```

The notebook then obtains the background spacing at the cavity location and
calculates a wall-refinement width:

```python
hBGAll = NNGeometryNN.getHBG(thickness, allCavities, gridSize)
etaUse = 0.5
wallRefineWidthAll = NNGeometryNN.getRefineWidths(
    tmInCavity,
    allCavities,
    hBGAll,
    eta=etaUse,
    minRefine=20.0,
)
```

`etaUse` controls the refinement criterion near the cavity wall, while
`minRefine` imposes a minimum refined width of 20 m. The resulting refinement
boxes are clipped to the simulation's vertical bounds and used to partition
the medium into numerical integration blocks.

For reproducible validation, keep `etaUse` consistent between the numerical
run, output filename, and comparison cell.

## Selecting the body wave

The user selects one deterministic plane wave near the beginning of the first
cell:

```python
wType = "Px"
```

Supported values are:

| `wType` | Propagation direction | Displacement/polarization | Compared acceleration component |
| --- | --- | --- | --- |
| `Px` | +x | P displacement along +x | x |
| `Pz` | +z | P displacement along +z | z |
| `SHx` | +x | SH displacement along +y | y |
| `SHy` | +y | SH displacement along +x | x |
| `SVxz` | +x | SV displacement along +z | z |

The notebook first calls `simDisp.genBodySrc`, but then overwrites its random
metadata to construct exactly one unit-amplitude, zero-phase wave. The unwanted
wave family is retained as a dummy entry with zero amplitude. This preserves
the data structure expected by the shared body-wave routines.

For example, `Px` sets a unit P wave propagating along +x and makes the S-wave
amplitude zero. `SHy` sets an S wave propagating along +y with polarization
along +x and makes the P-wave amplitude zero.

The fallback `else` branch defines the `SVxz` case. Use one of the documented
strings exactly; an unrecognized value will also enter this fallback branch.

## Wavefield flags

The main configuration must select analytic body-wave mode:

```ini
[simFlags]

if_full_field = False
save_hv = False
```

`if_body = True` is valid only for a homogeneous medium. In this example,

deterministic wave in every realization.

The notebook calls

```python
splitAll = createDB.createFinalInputs(config)
```

even though the body-wave displacement field is analytic. These calls remain

The actual Qseis execution line is commented out:


## Frequency grid and reference displacement

The analysed FFT bins are constructed from `t_max`, `n_samp`, and the requested
frequency band:

```python
freqOut, idxFreq, df_native = simDisp.getFreqGrid(
    tMax, nSamp, fMin, fMax, df
)
```

For every realization, the notebook also evaluates the displacement at the
surface and at the cavity depth:

```python
zList = [0.0, cavDepthUse]
simDisp.getSurfDeepBodyDispPerRea(...)
```

These reference displacements support later RMS assembly and scaling. They are
saved under `out_disp_rea` even though the semi-analytic validation cell works
directly with the NN output.

## Numerical NN calculation

The medium is divided into layers and blocks. Each block contributes a volume
term, and only outer-domain faces contribute truncation-surface terms.

The notebook accumulates four complex arrays, each with shape
`(n_frequency, 3, n_test_mass)`:

| Array | Meaning |
| --- | --- |
| `IBlockTot` | Bulk/volume contribution integrated over the material domain. |
| `IVertFaceTot` | Contribution from vertical outer truncation surfaces. |
| `IHorFaceTot` | Contribution from horizontal interfaces and outer horizontal surfaces. |
| `ITot` | Total Newtonian acceleration after applying the boundary corrections. |

For each block, `NNCompute.runVolNNComputeBlock` evaluates the volume integral.
Vertical faces are included only when `f.isBoundary` is true.
`NNCompute.handleHorSurfNN` handles horizontal material interfaces and the
top/bottom treatment appropriate to `fullSpace`.

After all blocks and layers have been processed, Newton's gravitational
constant is applied:

```python
IVertFaceTot *= G
IHorFaceTot *= G
IBlockTot *= G
```

The total is assembled using the sign convention

```python
ITot = IBlockTot - IVertFaceTot - IHorFaceTot
```

The arrays represent complex frequency-domain Newtonian acceleration. For the
unit-amplitude deterministic waves used here, their magnitudes can be read as
the acceleration response per unit displacement amplitude.

## Output file

The realization result is saved under `out_disp_rea` with the name

```text
NNFullRea<realization>Eta<etaUse><wType>Rad<radius>.npz
```

For the default example, the filename is

```text
NNFullRea0Eta0.5PxRad20.0.npz
```

It contains:

- `IVertFaceTot`;
- `IHorFaceTot`;
- `IBlockTot`;
- `ITot`; and
- `freqOut`.

The comparison cell must use the same `etaUse`, `wType`, and sphere radius or
it will attempt to load a different filename.

## Semi-analytic validation

Run the second notebook cell immediately after the numerical calculation, or
update its configuration path and filename parameters to match an earlier run.

The cell loads the numerical arrays and evaluates the corresponding
semi-analytic transfer terms from `modules/bodyPSNN.py`. Depending on `wType`,
it calls one of:

- `P_x_sphere_all_components_shifted`;
- `P_z_sphere_all_components_shifted`;
- `SH_x_y_sphere_all_components_shifted`;
- `SH_y_x_sphere_all_components_shifted`; or
- `SV_x_z_sphere_all_components_shifted`.

Each routine returns bulk, vertical-surface, horizontal-surface, and total
geometric response terms. The notebook converts them to acceleration using

```python
A = G * rho * xi0 * H
```

where `xi0 = 1.0` is the unit displacement amplitude.

Three panels compare:

1. numerical and semi-analytic bulk contributions;
2. the relevant vertical or horizontal boundary contribution; and
3. numerical and semi-analytic total Newtonian acceleration.

For `Px`, `SHx`, and `SHy`, the second panel shows the vertical-boundary term.
For `Pz` and `SVxz`, it shows the horizontal-boundary term.

The final plot shows the absolute total-response error:

```python
errOut = np.abs(A_total[:, compPlot] - Itot[:, compPlot, 0])
```

This comparison is the primary validation product of the notebook. A successful
run should show numerical points following the semi-analytic curves over the
analysed frequency band. The residual error should be assessed while refining
the wavelength grid and the cavity-wall integration region.

## Running the example

1. Copy or select the full-space or half-space main configuration.
2. Set its output paths to existing writable directories.
3. Select the matching spherical-cavity file.
4. Set `wType` to one of the five supported wave cases.
5. Set `fullSpace` consistently in both notebook cells.
6. Keep `n_rea = 1` for the deterministic validation.
7. Run the first cell to construct the geometry and calculate the numerical NN.
8. Confirm that the expected `.npz` file appears in `out_disp_rea`.
9. Make the comparison-cell parameters match the numerical run.
10. Run the comparison cell and inspect the three contribution plots and the
    absolute-error plot.

## Important consistency checks

Before interpreting a comparison, verify that:

- the main configuration represents a homogeneous medium;
- `if_body = True`, while `if_ray` and `if_full_field` are false;
- the configuration, cavity file, `fullSpace`, and validation bounds describe
  the same physical problem;
- the cavity centre and selected test mass coincide when validating the centred
  semi-analytic solution;
- `wType`, `etaUse`, radius, and output filename agree between both cells;
- the semi-analytic `L` matches the numerical domain half-width;
- `vP`, `vS`, and `rho` used by the comparison cell come from the same model;
- the output frequency vector matches the numerical result; and
- changes in `lambda_res` or wall refinement lead toward a converged result.

## Scope and limitations

This notebook is a controlled validation case rather than a realistic seismic
noise prediction. It uses one coherent, unit-amplitude plane wave in a
homogeneous medium and a test mass at the centre of one spherical cavity.

The next body-wave example, `getSphNNStochBody.ipynb`, extends the calculation
to multiple randomly oriented P and S waves and many stochastic realizations.
