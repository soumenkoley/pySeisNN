# pySeisNN: Newtonian noise in 1-D layered media

**pySeisNN** simulates seismic displacement fields and calculates the
associated Newtonian noise (gravity-gradient noise) around underground test
masses and cavities. It is designed for studies in homogeneous and
horizontally layered elastic media, with particular support for geometries
relevant to the Einstein Telescope.

The repository combines analytic homogeneous-medium wavefields with numerical
Green's functions generated by **Qseis**. It supports deterministic validation
problems, stochastic seismic-source ensembles, spherical and cuboidal
cavities, and separate evaluation of the volume and boundary contributions to
Newtonian acceleration.

The project is distributed as a collection of documented Jupyter notebooks,
Python modules, example configurations, reference data, and the Qseis input
template required by the database generator.

> **Research-software status:** calculations should be checked for spatial,
> frequency, time-window, domain-size, and realization-count convergence before
> they are used for scientific conclusions. The supplied configurations are
> reproducible examples, but their absolute filesystem paths must be adapted to
> each installation.

## What the software can do

- Generate analytic P- and S-wave fields in a homogeneous full space or
  half-space.
- Generate analytic Rayleigh-wave fields in a homogeneous half-space.
- Generate full seismic fields in homogeneous or layered half-spaces from
  Qseis Green's functions.
- Simulate deterministic waves, a prescribed point force, or stochastic
  ensembles of simultaneous sources.
- Place stochastic sources inside the simulation region or on an exterior
  ring.
- Model spherical and rotated cuboidal cavities with locally refined spatial
  grids.
- Calculate bulk, vertical-boundary, horizontal-surface/interface, and total
  Newtonian acceleration.
- Evaluate several test masses and cavities without double-counting overlapping
  refined regions.
- Calculate seismic cross-correlations, two-dimensional displacement fields,
  and surface-to-depth attenuation.
- Compare Qseis displacement and Newtonian-noise results with independent
  SPECFEM3D simulations.
- Scale stochastic results to measured surface or underground displacement
  amplitude spectral densities.

## Physical workflow

```text
1-D geology + sources + domain + cavities
                    |
                    v
       analytic field or Qseis GF database
                    |
                    v
          frequency-domain displacement
                    |
                    v
      volume and boundary NN integration
                    |
                    v
 per-realization results -> RMS spectra -> ASD scaling
```

The analytic body- and Rayleigh-wave modes are intended for homogeneous media.
Layered geology must be treated with the Qseis full-field mode, which includes
the response of the configured one-dimensional velocity and density model.

## Quick start

The documented setup targets 64-bit Linux and uses Conda. From the repository
root, create and activate the supplied environment:

```bash
conda env create -f environment.yml
conda activate pySeis1DNN
```

Verify the Python environment:

```bash
python -c "import numpy, scipy, matplotlib, joblib, pysurf96; print('Dependencies OK')"
python -c "from modules import configLoader, createDB, gfLoader, simDisp, NNCompute; print('Project imports OK')"
```

Next:

1. Follow the [installation guide](docs/installation.md), including compilation
   of Qseis for full-field calculations.
2. Select a starting INI file from `AllConfigFiles/` and replace every
   machine-specific entry in its `[paths]` section. The
   [distributed-configuration guide](docs/distributed_configurations.md)
   identifies the correct files for each notebook.
3. Create dedicated writable directories for Qseis inputs and calculation
   outputs.
4. Start Jupyter from the repository root:

   ```bash
   jupyter lab
   ```

5. Begin with one of the analytic single-wave tutorials, or with the
   single-force validation notebooks if a working Qseis installation is
   already available.

The repository is currently run directly from its source directory; installing
it into `site-packages` is not required.

## Qseis integration

Full-field calculations use the Qseis 2006b backend distributed through
[`fomosto-qseis`](https://git.pyrocko.org/pyrocko/fomosto-qseis). Qseis is an
external program and is not included in this repository.

The pySeisNN-specific master input template **is** included at:

```text
qseisTemplates/qs6inpNTempN.dat
```

Set `template_file` to this file and `qseis_exe` to the locally compiled Qseis
binary. Do not edit the master template for individual jobs: pySeisNN generates
the run-specific Qseis inputs from the physical and numerical configuration.
See [installation](docs/installation.md#qseis-template) for the complete setup.

## Configuration at a glance

A calculation normally uses:

- one primary `configParse*.ini` file defining the geology, grids, sources,
  paths, simulation mode, and parallel settings;
- one cavity INI file defining spherical or cuboidal cavity geometry;
- one driver notebook or an exported Python script; and
- for full-field mode, a compiled Qseis executable and a compatible GF
  database.

All distances are in metres, velocities in metres per second, densities in
kilograms per cubic metre, and frequencies in hertz unless stated otherwise.
User-facing test-mass and cavity depths are positive downward. The software
performs the conversion to its internal Cartesian z convention.

The principal wavefield flags are:

| Mode | `if_body` | `if_ray` | `if_full_field` | Valid medium |
| --- | ---: | ---: | ---: | --- |
| Analytic P/S waves | `True` | `False` | `False` | Homogeneous only |
| Analytic Rayleigh waves | `False` | `True` | `False` | Homogeneous half-space only |
| Qseis full field | `False` | `False` | `True` | Homogeneous or layered |

Exactly one mode should be enabled.

## Running larger calculations

Notebook workflows can be exported for non-interactive execution:

```bash
jupyter nbconvert --to script getSphNNStochBody.ipynb
python getSphNNStochBody.py
```

Before submitting a batch calculation, use dedicated input and output
directories, confirm the allocated worker counts, and run a reduced case. The
normal low-I/O production settings are:

```ini
save_hv = False
on_fly_nn = True
```

See the installation and basic-usage guides for batch-execution and convergence
recommendations.

## Output and data safety

The software can generate large Green's-function databases and realization
archives. Two settings deserve particular attention:

- Input generation removes top-level Qseis `.dat` files from `input_folder`.
- With `qseis_out_del = yes`, existing Qseis run directories can be deleted
  and rebuilt.

Never point `input_folder` at a directory containing unrelated or
irreplaceable files. Several tutorial configurations intentionally reuse a
common output location, so assign separate paths when results must be retained.

## Validation and reproducibility

The repository contains single-force homogeneous and layered validation
workflows that compare Qseis-based calculations with independent SPECFEM3D
results. SPECFEM3D is needed only to reproduce those external simulations; it
is not required for standard pySeisNN calculations.

For reproducible production results, retain:

- the primary and cavity INI files;
- the notebook or exported driver used for the run;
- the pySeisNN and Qseis revisions;
- the Qseis template and assembled GF metadata;
- source metadata and random seeds when exact stochastic replay is required;
  and
- the realization-level output archives.

The current tutorial drivers do not consistently save stochastic random seeds
or complete source metadata. Add explicit seed and metadata handling when exact
realization-by-realization reproducibility is required.
